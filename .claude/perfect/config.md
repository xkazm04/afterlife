## Repo law
- Read `AGENTS.md`/`CLAUDE.md` first: this Next.js has breaking changes; read the relevant guide in `node_modules/next/dist/docs/` before writing Next code.
- Hard structure rules (enforced by `npm run check:structure`): a file is at most 200 lines; a folder holds at most 10 files.
- Layout: `src/app/<route>/page.tsx` server route; `src/app/features/<screen>/{components,hooks,model,data}` with pure tested `model/`; shared kit in `src/components/` (documented in `src/components/README.md`); reuse the kit before building.
- Tokens only (`src/styles/tokens.css`); keep accessible names/focus rings (scan-sweep fixed many; do not regress). Both text sizes (Smaller/Standard/Larger) must work.
- Writes are always the person's: no feature may write to GitLab without a click and a shown command.
- `DECISIONS.md` overrides README and docs/plan. Demo data is illustrative; label it as such.
- Out of scope walls: `gitlab/` flows and `policy/` templates, `.env*`, `engine/` proof semantics (claims vs checks split), licence files.
- Push only on the user's say-so; when pushing, push BOTH `github` (canonical) and `origin` (GitLab hackathon).
