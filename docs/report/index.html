The vision, mapped

Two pillars, now on screen

Easy onboarding of company IT systems
  • /onboard takes the whole estate (184 projects) through a funnel: discovered, baselined, paired, watching, in cycles.
  • Every read runs on its own; writes are capped per batch and go as you, after the exact commands.
  • Merges, tokens and unfinished setups stay in an "only you" list for the whole estate.
  • The estate baseline names the weakest stage as the theme for the first cycles.
Infinite rounds of reliable improvements, designed in the app
  • /cycles replays every stage from day 0; the screen proves its own numbers (replay = scan, chain holds).
  • A cycle closes only when a same-engine rescan credits or rejects each change; misses carry forward.
  • The designer plans the next round with rules that keep credit attributable.
  • Each closed cycle produces a Markdown hand-back report, ready to post as an issue.
The loop

Every cycle walks six phases, then feeds the next

1Scanthe engine rates nine stages
2Pickyou choose the gaps; T6 only proposes
3Sendone MR per gap, as you, commands first
4Mergea person merges; no merge token
5Provejobs run on main and leave evidence
6Creditsame-engine rescan credits or rejects
↺

Amber marks the phases that wait for a person, the same rule the app uses everywhere. Design rules: one change per stage, at most four per cycle, nothing on a stage the running cycle is lifting, and an unknown rung is probed before anything lifts it.

How quality was kept

Nothing pushed on trust

3 reviews

Independent agents reviewed Cycles and Onboard, and audited every screen visually. Each finding was traced, fixed and pinned by a test where it was logic.

Clean checkout

Before each push, a fresh worktree of HEAD was typechecked, linted and tested. It caught a commit missing files that .gitignore had silently excluded.

verify + smoke

npm run verify runs types, lint, structure rules (200 lines per file, 10 files per folder), 999 tests and a production build. npm run smoke covers the layout.

Worth knowing

  • One pushed commit did not build (dee830b): a folder named design/ is gitignored repo-wide. Fixed in the next commit; the clean-checkout gate now prevents it.
  • Left as is: on the front door at the largest text and 1280 px, the left-hand stats overlap the city's towers. It is a design decision for the winning prototype's owner.
  • Simulated by design: Onboard runs and re-probes, cycle designs (kept for the browser session) and the closed cycle history are demo data, labelled as such on screen.
  • /docs/ is ignored except docs/features and docs/report, which now hold the module docs and this report.
